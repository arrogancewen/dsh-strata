# Strata · 记忆地层

**简体中文** | [English](README.en.md)

为 **DeepSeek Harness（DSH）** 提供本地、可迁移、带来源的持久记忆。让会话先找到简短线索，再按需要读取完整记忆与原始证据。

当前版本 **0.1.3**。设置页跟随 DSH 默认配色和深浅主题，支持桌面端的窄设置面板。记忆服务没有外部运行依赖，不需要下载嵌入模型。

## 功能

| 功能 | 当前行为 |
| --- | --- |
| 保存记忆 | 手动保存观察、主张、决定、待办、想法、结果和规则草案；DSH 会话可调用记忆工具 |
| 检索记忆 | 中文词法检索，返回有长度限制的梗概，再逐级读取正文和证据 |
| 历史版本 | 修改追加版本，支持按时间、提交水位或精确版本读取 |
| 使用范围 | 整个 DSH，或指定文件夹；可选择是否包含子目录 |
| 迁移与导入 | 导出完整包或引用包；导入 Strata JSON、Markdown、TXT，预览后确认 |
| 合并与副本 | 同来源合并、重复跳过、本地修改冲突拦截，也可另存为独立副本 |
| 原文回读 | 分页读取已归档证据，并检查哈希；原文缺失时明确报告 |
| 手动灵感盒 | 保存和查看想法；想法与规则草案默认不进入事实检索 |
| 设置界面 | 记忆总览、使用范围、迁移与导入、灵感设置；支持搜索、分页、文件上传下载 |

## 安装

需要 **Node.js 22.13 或更高版本**。已验证 DSH SDK **0.2.1-rc.2**，以及使用该 SDK 的 Desktop 环境；其他版本尚未完成验收。

### Desktop 桌面版

```sh
git clone https://github.com/arrogancewen/dsh-strata.git
cd dsh-strata
npm ci
npm run build
```

在 DSH 桌面版侧边栏进入“插件”，选择安装本地目录，指向克隆得到的 `dsh-strata` 文件夹并启用。按宿主提示重载后，打开 **设置 → 记忆地层**。

仓库包含 `lib/client.js` 构建产物；修改界面源码后需要重新执行 `npm run build`。`esbuild` 仅作为构建依赖。本项目尚未发布到 npm registry，请使用本地目录或自行生成的安装包。

### Web profile

完成上述克隆与构建后，在项目目录运行：

```sh
dsh plugin --profile web add .
```

然后重启对应的 Web 实例。Desktop 的 CLI 安装流程与 Web 不同，桌面版优先使用内置插件管理器。

### 独立本地设置页

```sh
npm start
```

打开 `http://127.0.0.1:4318`。这是与插件共用记忆核心的独立管理入口，默认使用项目中的 `.local/memory` 空库，范围为当前项目目录。

如需管理其他记忆库，可以指定绝对路径：

```sh
node src/server.mjs --root /absolute/path/to/memory --cwd /absolute/path/to/project --port 4318
```

Windows 示例：

```powershell
node src/server.mjs --root C:/memory/strata --cwd C:/projects/my-project --port 4318
```

本地服务仅监听 `127.0.0.1`，使用每次启动生成的页面访问令牌，并校验 Host 和 Origin。用 `Ctrl+C` 停止前台服务。

## 功能逻辑

### 1. 保存与逐级回忆

```mermaid
flowchart LR
    A[设置页手动保存 / 会话 remember] --> B[校验类型、来源与范围]
    B --> C[追加不可变版本]
    C --> D[L0 简短线索]
    D --> E[recall 检索梗概]
    E --> F[zoom 读取完整记忆]
    F --> G[deep 分页回读原文]
```

- 保存时生成条目 ID、版本哈希与提交水位，记录类型、来源和证据引用。修改需要带当前版本，避免覆盖另一会话的新提交。
- L0 只注入少量标题、类型与认知状态，作为历史资料进入上下文。当前按 UTF-8 字节保守限制长度，尚未使用模型 tokenizer 精确计量。
- `recall` 使用本地词法匹配：中文按相邻双字切分，查询词须全部命中，不在无结果时改为宽泛 OR 搜索。单条梗概最多 1,200 个 JavaScript 字符串单元，条目列表合计最多 16,000 字节，支持固定视图下继续分页。
- `zoom` 返回完整记忆、来源指针和状态；`deep` 通过条目绑定读取已归档证据，默认每页 8,000 个字符串单元，最多 20,000。
- 没有归档原文的手动记忆仍可保存和检索；调用 `deep` 会报告 `source_unavailable`，不会把记忆正文当作原始会话。

| DSH 工具 | 用途 |
| --- | --- |
| `strata_remember` | 用户要求记住信息时保存一条记忆，可引用已有条目作为派生来源 |
| `strata_recall` | 在当前允许范围内检索梗概，返回条目 ID、版本和固定视图 |
| `strata_zoom` | 读取指定条目的完整内容，可指定历史视图或精确版本 |
| `strata_deep` | 分页读取该条目引用的原始证据 |

### 2. 会话范围与权限

设置页可选择“整个 DSH”或“指定文件夹”，并控制是否包含子目录。整个 DSH 指接入同一记忆库的 DSH 会话，不代表其他软件自动共享该库。

会话权限来自宿主提供的真实工作目录和会话身份。模型传入的 `cwd`、`admin` 等字段不能提升权限。路径通过实际目录解析后按目录边界判断，避免把同名前缀目录误认为子目录。

读取必须同时满足记忆空间总范围、条目范围、已有证据范围以及派生来源的当前限制。历史读取仍按当前权限检查。派生条目继承可兼容来源中更窄的范围，来源之后收窄权限时，已有派生条目也受限制。

会话工具不能放宽已有条目范围或移除派生链。管理设置和迁移操作由 DSH 所有者执行，管理页可以查看全库。

### 3. 来源、证据与想法

记录类型与认知状态分别保存。想法（`idea`）和规则草案（`rule_draft`）默认不参与事实检索；来自这些候选的派生记录也保持候选性质，普通会话不能通过改类型把它们转成事实。

助手写入和导入内容不会自行获得 `supported` 状态。会话工具不能提交自行编造的原文证据或导入身份。导入文件中的文字按资料保存，不执行其中的指令。

证据哈希校验说明保存的内容完整，**不代表内容中的主张已被证实**。自动会话采集尚未接入，所以手动保存一条记忆并不等于已经归档整个会话。

### 4. 迁移与导入

```mermaid
flowchart LR
    A[选择 JSON / Markdown / TXT] --> B[校验格式、哈希和版本链]
    B --> C[选择合并 / 副本与目标范围]
    C --> D[只读预览新增、更新、重复和冲突]
    D --> E[用户确认]
    E --> F[检查预览水位并原子提交]
```

1. **导出**：完整包包含当前及历史版本和引用的可用原文；引用包保留条目与来源指针，不携带原文。原文已缺失时不能导出完整包，可改选引用包。
2. **校验**：检查包与证据哈希、条目版本、线性历史链及来源引用。预览不会写入记忆。
3. **映射范围**：文件夹限定的来源必须绑定到本机有效文件夹，不能直接扩大成全 DSH 可用。多个来源文件夹统一映射时需明确指定目标；导入不会改变记忆空间的总范围。
4. **合并或副本**：合并按来源身份和版本识别重复及更新；目标库存在不同的本地修改时拦截冲突。副本分配独立条目身份。相同迁移计划重复确认不会反复新增。
5. **确认提交**：预览十分钟后过期。预览后有其他提交时要求重新预览；导入通过同一事务提交条目、证据和回执。
6. **原文补全**：引用迁移缺原文时保持不可回读，外部 ID 不会误连到本库同名证据。之后合并同来源完整包可以补回原文。缺失的派生依赖会在预览中提示，相关条目仅供管理员查看。

Markdown/TXT 文件按整份文本保存为一条未验证主张，并保留原始文本证据。没有可靠来源日期时显示“来源时间未知”。

| 导入限制 | 上限 |
| --- | --- |
| JSON 包 | 12 MiB，最多 10,000 个版本和 10,000 项证据 |
| Markdown / TXT | 512 KiB，且不超过 262,144 个字符串单元 |

当前不直接导入 DSH 会话 ZIP、任意旧系统数据库或角色卡；可先把需要保留的旧记忆整理为 Markdown/TXT。

### 5. 存储与并发

权威数据保存在 `.history/commits` 的不可变 JSON 快照中，`HEAD.json` 原子指向当前提交。写入通过文件锁串行化，修改追加版本，失败的事务不发布。一个库可由多个进程访问。

`memories/*.md` 是供人阅读、可重建的投影，直接编辑这些文件不会写回记忆库。检索可以使用时间、`viewId` 或精确 `revision`；目标库使用自己的提交水位，并保留导入来源的版本身份。

插件默认数据目录为 `~/.dsh/strata`，首次创建默认允许整个 DSH 使用。独立本地设置页默认使用另一份 `.local/memory` 库；管理同一份数据时需让 `--root` 指向插件目录。

需要自定义插件目录时，可在对应 profile 补丁中配置：

```yaml
- id: dsh-strata
  config:
    root: '/absolute/path/to/memory'
```

Windows 下也可使用 `C:/memory/strata`。重启和重新安装不会把已有范围设置重置为初始值。

## 当前边界

- 自动会话采集、压缩后工作状态重放、自动“灵光一闪”投递、人格与角色卡、语义冲突检测和经验提炼尚未实现；设置页提供手动灵感盒，自动开关禁用。
- 当前为全状态快照和本地词法检索，单个状态限 64 MiB；尚未对大库进行性能验收。
- 当前界面文字以中文为主，英文 README 用于项目说明；尚未提供完整英文界面。
- 运行时 `engines` 范围内的其他 DSH 版本不代表均已验收。rc.2 适配包含特定的 RPC 注册兼容路径，升级宿主后应重新验证。
- 项目当前标记为 `UNLICENSED`，尚未授予开源许可证。

## 开发与验证

```sh
npm ci
npm run build
npm run check
npm test
npm run test:dsh
npm run test:browser
npm run pack:check
```

- `npm test`：核心、应用、HTTP、迁移及宿主适配测试，覆盖并发、历史权限、范围继承、证据回读、冲突与重复导入。
- `test:dsh`：使用本机真实 SDK 做隔离验证，不修改运行中的 DSH；客户端部分检查模块与设置页注册结构。找不到 SDK 时明确输出 `SKIP`。可通过 `DSH_SDK_ROOT` 或 `node scripts/verify-local-dsh.mjs /path/to/dsh/node_modules` 指定 SDK。
- `test:browser`：使用本机 Chrome 和临时库验证真实按钮、文件上传下载、分页、错误提示、深浅主题及窄面板。可通过 `CHROME_PATH` 指定 Chrome。报告和截图保存在 `.artifacts/`。
- `npm pack`：生成包含客户端构建产物的安装包。

```text
src/core/           存储、版本、范围、中文检索、证据
src/transfer.mjs    迁移校验、预览计划、原子导入
src/application.mjs 共享业务接口与权限
src/host/           DSH RPC、工具和 L0 适配
src/server.mjs      独立本地设置服务
client/            设置页和 DSH 客户端入口
lib/client.js      DSH ModuleLoader 构建产物
tests/             自动化测试
```
